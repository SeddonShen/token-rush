# 在 A800 服务器上运行 Token Rush（8 × A800-SXM4-80GB，sm_80 架构）

`a800` 分支截至 2026-10-06 的状态。下面所有数字都是在这台机器上实测的，不是抄规格表。

## 这台机器

- 8 × A800-SXM4-80GB，驱动 580.95.05，CUDA 13.0（装在 `/usr/local/cuda-13.0`；`nvcc` 在那里，但不在 PATH 里）。**GPU 0/3/5/7 归我们用；1/2/4/6 跑着同事的 vLLM，不要碰。** 我们固定用 3 号卡。
- Python：uv 托管的 3.10.22（`uv python install 3.10`）。原因：系统自带的 3.10 没有开发头文件（Python.h），而 Triton 第一次编译它的驱动层时必须用到。仓库里的虚拟环境是 `.venv/`，创建命令：
  `UV_CACHE_DIR=/media/disk/shensd/learn_jev/.uv-cache uv sync --extra bench`
  （那个缓存里已经有 torch 2.14.0+cu130 的 Python 3.10 轮子——所以 torch 几乎零下载）。
- 每次跑之前设两个环境变量：`PATH="$PWD/.venv/bin:$PATH"`（让 Marlin 扩展编译时能找到 venv 里的 ninja）和 `CUDA_VISIBLE_DEVICES=3`（只用 3 号卡）。

## 下载路线（国内网络，全部实测过）

原则就一条：**每个东西走实测最快的路**，代理和国内直连混着用，不迷信任何单一方案。

| 要下什么 | 走哪条路 | 实测速度 |
|---|---|---|
| int4 检查点 17 GB（`zyhector/Qwen3.8-27B-TokenRush-int4g128`，魔搭上没有，只有 HF 有） | mihomo 代理 `127.0.0.1:7890`，curl 加 `--http1.1`，单流下载 | ~9.4 MB/s（试过 4 路并行分块，**不叠加**，瓶颈是代理链路本身） |
| DFlash2 草稿模型 3.85 GB（`z-lab/Qwen3.8-27B-DFlash2`） | 魔搭（ModelScope）直连，**不走代理** | ~14.8 MB/s |
| torch 及其他 Python 依赖 | uv，复用 learn_jev 项目的缓存 | ~0（缓存命中） |

两个模型都放在 `/media/disk/shensd/models/` 下：`tokenrush-int4g128/`（4 个分片，共 17.05 GB）和 `dflash2/`（config.json + model.safetensors，字节数与发布端逐字节核对过）。

其他结论：hf-mirror.com 从这台机器不可达（弃用）；HF 不走代理完全不可达。走代理跑 uv / git 时遵守 learn_jev 备忘录里的老规矩：只用 HTTP/1.1（这条链路会掐掉 HTTP/2）、HF 下载加 `HF_HUB_DISABLE_XET=1`、大包绝不用 pip（会卡死），一律 uv。

## 为 sm_80（Ampere）改了哪些代码

- `tokenrush/marlin.py`：编译扩展时**自动探测当前显卡的架构**，不再写死 5090 的 `12.0`。在 sm_80 上约 15 秒编好；数值已对照反量化参考实现验证（最大相对误差 0.6%，属于 bf16 累加的正常噪声级）。
- `pyproject.toml`：Python 要求放宽到 `>=3.10`（确认过代码里没有任何 3.11+ 的语法）。
- `scripts/env_check/check_bandwidth.py`：规格表带宽常数从 1792（5090）换成 2039（A800-SXM4-80GB）；`check_env.sh`：nvcc 的目标架构从 `nvidia-smi` 里取，不再写死。
- `tests/`：三个 fp8 测试在 sm_89 以下的卡上自动跳过（A800 跑 bf16 的 KV cache——这本来就是 `State` 的默认值；fp8 是作者在 32 GB 卡上为省显存做的技巧，80 GB 完全用不着）。另外三个"自己跟自己比"的阈值刚好贴着 bf16 舍入噪声的地板，在 Ampere 上差了一线，按实测值做了最小放宽，注释里都写了数字。**所有对照 PyTorch 参考实现的差分测试一行没改、全部通过：85 过，11 跳，0 挂。**
- 唯一没移植的：fp8 KV cache。Ampere 没有原生 fp8 指令；而且 bf16 的 KV cache 放 256k 上下文在 80 GB 里绰绰有余。

## 这张卡上的第一批数字（注意：kernel 参数还完全是按 5090 调的）

- **实测读带宽墙：1902 GB/s**，是规格表 2039 的 93.3%——比 5090 的 1701 还高。4.25 bit/权重下，raw 解码的理论上限 ≈ 133 tok/s。
- raw 解码（不开投机）：**81 tok/s**，只吃到墙的 61%。作者在 5090 上能拿 80–85%。**这个差距是纯粹的 kernel 重调空间，不是移植问题。**
- DFlash2 投机解码：**139 tok/s**（平均每步收下 2.53 个草稿 token，每步 18.2 ms）。
- MTP 投机解码：**128 tok/s**（每步收 2.33 个）。中文提示词会自动选它。

## 怎么跑

```bash
cd /media/disk/shensd/learn_inference/token-rush
export PATH="$PWD/.venv/bin:$PATH"
CUDA_VISIBLE_DEVICES=3 .venv/bin/python -m tokenrush.run --chat \
    --prompt "Explain speculative decoding in three sentences." \
    --model /media/disk/shensd/models/tokenrush-int4g128 \
    --dflash-path /media/disk/shensd/models/dflash2
```

权重 16.19 GB，运行状态 3.37 GB，显存共分配 21.72 GB。顺带一提：bf16 全精度参考模型（54 GB）也放得进这张卡——这是 5090 永远做不到的，意味着可以在这台机器上做 int4 与 bf16 的逐 token 对拍。

## 下一步：真正的学习课程

现在的引擎等于"没调过的引擎跑在一张更快的卡上"。接下来照着 `docs/progress.md` 的第 3 → 28 步重走一遍：**对着这张卡实测的字节数**，把每个 Triton kernel 的启动参数（block 大小、num_warps、split-K 份数）按 108 个 SM / 1902 GB/s 重新调。

- 第一个目标：raw 解码从墙的 61% 提到 ~85%（约 113 tok/s）。投机解码的速度会按比例跟着涨。
- 附带一个现成的练习：Marlin 原版有一个 L2 缓存的 evict-first 提示，在 5090（sm_120）上硬件不支持，作者被迫删掉了；在 Ampere 上它是合法指令，可以加回来——正好练手"读别人的 kernel 改优化"。
